# Squeeze

**Demo video (2:21):** https://youtu.be/EXrJVzd783o

Squeeze turns token-heavy inputs (slide decks, PDFs, web pages, JSON tool output) into compact, LLM-ready Markdown, and reports exactly how many tokens it saved.

Meta's **Muse Spark** reads every image of 64 px or more (up to 40 per file) and decides what it is worth: logos and stock photos are dropped, charts become data tables, diagrams and screenshots become short factual descriptions. A fact check, also run by Muse Spark, asks questions of the original text and answers them from the compressed text, so the saving comes with evidence that the text steps kept the facts.

> **Built during the Meta Global AI Developer Hackathon (Oct 26 – Nov 4, 2026).** All code in this repository was written during the event; the commit history shows it. Open-source libraries it depends on are listed in `pyproject.toml`. Test and eval files are generated by `tests/make_fixtures.py`, so the repo owns all of its content.

## Why

Context costs money, time and accuracy. A 1920×1080 slide image costs about 1,560 tokens on a typical vision model; a PDF sent natively is billed as text plus a page image per page; raw HTML is often 5–10x the size of its text. Most of that is waste: footers repeated on every slide, logos, markup, `null` fields, tracking parameters. Shorter context also tends to give better answers.

## Where Meta's models come in

| Step | Model | What it does |
| --- | --- | --- |
| Image triage | Muse Spark (Meta Model API), or Muse Spark Open | Classifies each image as informative, decorative or text; writes a chart's data as a table, a diagram's facts as text, transcribes text images |
| Fact check | Muse Spark | Writes 8 questions from the extracted text, answers them from the compressed text, judges each answer. It checks the text steps; it does not re-check image descriptions |

Everything else is deterministic code that runs before any model call, so the model only sees what survives:

1. **Extract** the content: slide text, tables and speaker notes (`python-pptx`); page text and figures (`pypdfium2`); the article of a web page (`trafilatura`); JSON with `null` and empty fields pruned and uniform arrays turned into tables.
2. **Images**: skip anything under 64 px (no call), send each unique image once (a repeat points back to the first), downscale to 1024 px JPEG, at most 40 calls per file, cache every answer on disk by backend, model and content.
3. **Clean**: drop base64 blobs and data URIs, strip tracking parameters, alias UUIDs and hashes that repeat, keep repeated footers and template lines once, normalize whitespace (indentation kept).
4. **Render** Markdown with anchors like `[slide 4]` or `[p12]`, plus a manifest with token counts per step.

## Setup

```bash
pip install -e ".[dev]"
cp .env.example .env     # then fill in your keys; .env is git-ignored
```

Backends, set with `SQUEEZE_BACKEND` in `.env`:

- `meta-api` (default): Muse Spark on the Meta Model API. Only `META_API_KEY` is required; the base URL defaults to `https://api.meta.ai/v1` and the model to `muse-spark-1.3`.
- `openai-compat`: Muse Spark Open on Baseten or Modal. Set `OPENAI_COMPAT_BASE_URL` and `OPENAI_COMPAT_API_KEY`; the model defaults to `meta-models/muse-spark-open-1026`.
- `mock`: offline stand-in for tests and dry runs. Its image text is a placeholder, never a real result.

Squeeze reads `./.env` when it starts; variables already set in your shell take priority. The first run downloads tiktoken's vocabulary file once, so run it online before a demo.

## Use

Web app:

```bash
uvicorn squeeze.app:app --port 8000
# open http://localhost:8000 and drop a file
```

CLI:

```bash
squeeze deck.pptx report.pdf https://example.com/post --out out/
squeeze deck.pptx --images none        # no model calls, drop every image
squeeze deck.pptx --fidelity           # also run the Muse Spark fact check
```

Each input writes `out/<file>.md` and `out/<file>.manifest.json` (for example `out/deck.pptx.md`).

## How the numbers are counted

- Tokens are counted with `tiktoken` (`o200k_base`), never estimated from characters.
- "Tokens before" is the input sent the usual way: raw text for HTML and JSON; slide text plus every embedded image for PPTX; page text plus one page image per page for PDF, because native PDF input bills both. Image tokens use Anthropic's published formula for its standard vision tier (28 px patches, long edge 1,568 px, at most 1,568 tokens per image).
- Every step's saving is measured, and the steps add up exactly to the total.
- "Numbers kept" is a free check: the share of distinct numbers in the extracted text that are still in the output.

## Doesn't Muse Spark cost tokens too?

Yes. Squeeze records what every Muse Spark call used, from the API's own usage counts, and shows it in the web app, the CLI output and `manifest.json`. Live run on the demo files, Nov 4, 2026 ([run log](https://github.com/eshu3104/squeeze/actions/runs/41933623129)):

| File | Tokens saved per use | Muse Spark, image step (paid once) | Image step pays for itself | Fact check (optional audit, paid once) |
|---|---:|---:|---|---:|
| Slide deck, 3 images sent | 4,253 | 5,948 | on the 2nd use | 5,286 |
| PDF report, 2 images sent | 7,358 | 3,776 | on the 1st use | 6,403 |
| Web page | 2,684 | 0 | immediately | 5,330 |
| GitHub API JSON | 2,484 | 0 | immediately | 7,548 |

Why it is still worth it:

1. **Most of the saving costs no model tokens at all.** Extraction, footer removal, HTML cleanup and JSON pruning are plain code. The web page and the JSON made no image calls.
2. **The image step is paid once; the saving repeats every time the text is sent.** Every follow-up question, every agent turn and every teammate reuses the compressed text, and answers are cached, so re-runs cost nothing. An agent that re-reads the deck for 20 turns spends 5,948 tokens once and saves 85,060, a net 79,112.
3. **The fact check is an audit, not a step to run every time.** Use it to confirm that compression is safe for a kind of document, then leave it off.

Where it does not pay: a file with many images that you send once and never again. For that case, `--images none` keeps every free saving and makes no model calls.

Two caveats: Muse Spark's output counts include its reasoning (about 900 tokens per image call here), and output tokens usually cost more than input tokens, so compare against Meta's current pricing rather than counting tokens alone. "Tokens saved per use" is counted with `o200k_base` on the text your model receives; Muse Spark's counts come from its own tokenizer.

## Limits

- The Meta Model API request format is assumed to be OpenAI-style chat completions with base64 images (see `squeeze/muse.py`); confirm against Meta's quickstart.
- Web pages: images are not fetched; the article text and tables are kept.
- The fact check reads the first 12,000 tokens of a file.
- Not built: spreadsheets, logs, code repositories, Word files.
